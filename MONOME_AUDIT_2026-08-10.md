# mlrVST-modern — Monome Pages Audit (2026-08-10)

Correctness audit of every monome grid page plus grid workflow-enhancement proposals.
Method: three end-to-end code audits (page routing/key-LED consistency, per-page value math,
scene-mode surface), adversarial verification of all major findings, then two design passes
(live-performance lens, screen-vs-grid parity lens). CONFIRMED = verified by an independent
refute-by-default trace.

### CONFIRMED — Source/MonomeController.cpp:1753
Control-row column 13 is double-claimed: it is both the default StepEdit page-select button (controlPageOrder index 13, PluginProcessor.h:1513) and the StepEdit pitch-down utility, so once StepEdit is active the page can never be toggled off from its own button, and StepEdit never releases in momentary mode.

*Why:* Traced end-to-end in handleMonomeKeyPress (MonomeController.cpp:945). Default controlPageOrder[13] = StepEdit (PluginProcessor.h:1513) and NumControlRowPages = 14, so x==13 is the StepEdit page button. Once StepEdit is active, the key-down branch at MonomeController.cpp:1753 (stepEditModeActive && (x==13||x==14)) fires before the page-select/toggle branch at :1792 and returns after applyUserPitchControlToStrip (:1761), so latched mode can never toggle the page off from button 13 — each tap detunes the selected strip by -1 semitone. In momentary mode the key-up release branch (:2396-2408) requires !isMonomeControlRowUtilityCell(layout, x), but that function returns true for x==13 while layout.stepEditModeActive (PluginProcessorMonomeControls.cpp:182-183), so the release-to-Normal and wasStepEditMode cleanup are skipped and StepEdit latches; layout is re-captured per event (:949) so stepEditModeActive is true at release time. The LED claim also holds: the bright active-page level written at :3390-3392 for button 13 is unconditionally overwritten by the pitch-down level at :3435. Reordering StepEdit to buttons 0-12 avoids the trap, exactly as the claim states; the only monome escape is selecting a different page.

*Fix:* Exclude the page button currently mapped to StepEdit (via getControlButtonForMode(ControlMode::StepEdit)) from the 13/14 pitch-utility claim in both the key-down branch at MonomeController.cpp:1753 and isMonomeControlRowUtilityCell (PluginProcessorMonomeControls.cpp:182-183), or relocate the pitch-nudge cells off the page-button range (e.g. to x==14/15, since only 0-13 are page buttons), and correspondingly stop suppressing the momentary release at :2396-2399 for the button that activated the page.

### CONFIRMED — Source/MonomeController.cpp:1767

*Fix:* In the utility branch at MonomeController.cpp:1767, exclude columns that carry a page assignment (x < NumControlRowPages) or relocate the sample trigger-mode cells off columns 13-14 so they cannot shadow page buttons; alternatively require a modifier/hold for the sample utility cells.

### CONFIRMED — Source/PluginProcessorMonomeControls.cpp:279
On 8-wide monome grids (monome 64, vertical 128), control pages at button indices 8-13 (GroupAssign, Filter, Delay, Modulation, Preset, StepEdit in default order), the top-row edit toggle (col 15), and scratch/stutter (cols 8-15) are unreachable from the grid because page selection maps physical column directly to page index with no width-aware remapping or banking.
