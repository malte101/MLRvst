# Visual System Audit — mlrVST-modern UI

Files audited: /Users/e2_18/Downloads/mlrVST-modern/Source/PluginEditorStyle.h (71 lines, full read), PluginEditor.cpp (9,992 lines), PluginEditorPanels.cpp (15,711 lines), plus L&F classes in PluginEditor.h.

## 0. Headline finding: the style header is not actually the style system

- PluginEditorStyle.h defines 11 color tokens + drawPanel/styleUiButton/styleUiCombo — but **PluginEditor.cpp does not include it**. It re-declares all 11 tokens AND a verbatim copy of drawPanel in an anonymous namespace (PluginEditor.cpp:22-60). Only PluginEditorPanels.cpp includes the header (line 3). Any token change must be made twice or the two files diverge silently.
- Even the header's own helpers bypass its tokens: styleUiButton hardcodes 0xff3b4146/0xff4a5258/0xff141414, styleUiCombo hardcodes 0xff353b42/0xff6a7076 (PluginEditorStyle.h:45-64).

## 1. Palette reality

- **287 hardcoded `Colour(0x...)` literals** (134 in PluginEditor.cpp, 153 in PluginEditorPanels.cpp) resolving to **173 distinct hex values**, vs 11 named tokens. Plus 90 named colours (Colours::white ×66, black ×15, transparent ×9 — mostly alpha sheens/fake shadows).
- **~45 of those 173 are near-duplicate dark greys** between 0xff0e1114 and 0xff4a4d50 (e.g. 0xff232629 vs 0xff23262a vs 0xff23282d vs 0xff24272c all coexist). There is no elevation ramp — every surface got its own eyeballed grey.
- **Token usage where it exists**: kTextMuted ×113, kAccent ×106, kTextPrimary ×71, kTextSecondary ×20, kSurfaceDark ×18, kPanelStroke ×12. So text colors and accent are reasonably tokenized; surfaces/strokes are not.
- **Ad-hoc semantic colors, all untokenized**:
  - Green "active/connected/play": 0xff76be7e ×10 (monome status PluginEditor.cpp:6486-6493, transport play heads 7024/7123, status labels), plus variants 0xff88d96b, 0xff58c96d, 0xff6eb676 used for the same meaning.
  - Red "record/error": 0xffd46b62 ×9 (record heads, status labels, PluginEditorPanels.cpp:8285), plus 0xffd45b5b, 0xffc95252, and dim blink partners 0xff743636 / 0xff6d3434 (PluginEditor.cpp:4839, PluginEditorPanels.cpp:7374).
  - Blues/cyans: 0xff6bbcff (Speed), 0xff74d6ff (Delay), 0xff3bd5ff ("cyan contrast for yellow controls", PluginEditor.cpp:5136, 5763), 0xff41b7e8 (Break transition).
- **Duplicated palette functions**: `patternControlEventColour` — a 9-color per-ControlMode map — exists twice, verbatim (PluginEditor.cpp:63-86 and PluginEditorPanels.cpp:~478-490). The 7-color "Ableton-like" strip track palette is inlined twice too (PluginEditor.cpp:1483-1491 and ~7609).
- Amber kAccent doubles as fallback ControlMode color, panel accent ring, slider thumb, popup highlight, combo arrow — it is simultaneously the brand color and the "misc" color.

## 2. Typography

- **~36 distinct font sizes, 5.8pt to 23.0pt.** Distribution: 9.0 bold ×16, 8.0 bold ×12, 10.0 ×12, 10.0 bold ×10, 9.0 ×9, 12.0 bold ×9, 11.0 / 11.0 bold ×8 each — then a long tail of one-offs: 5.8, 6.0, 6.4, 6.8, 7.0, 7.2, 7.3, 7.4, 7.6, 7.8, 8.4, 8.5, 8.6, 8.8, 9.1, 9.2, 9.4, 9.5, 9.6, 9.7, 9.8, 10.2, 10.6, 10.8, 11.4, 11.5, 13.5, 23.0. It is chaos; the fractional sizes (9.6f, 8.4f, 7.3f) are clearly per-widget squeeze-to-fit tuning.
- **12+ call sites below 8pt bold** — micro-labels (6.0pt badge text in scene slots, PluginEditorPanels.cpp:3258; 5.8pt somewhere in a lane header). At 100% DPI these are borderline illegible — the opposite of glanceable.
- **Bold is the default weight** — the overwhelming majority of setFont calls are Font::bold, so weight carries zero hierarchy; size (in 0.2pt increments) is doing all the work.
- Typeface: single global "Helvetica Neue" via setDefaultSansSerifTypefaceName (PluginEditor.cpp:9742). No mono variant for numeric readouts.
- Per-role fonts are chosen inside L&F overrides with magic numbers: SceneControlLookAndFeel::getTextButtonFont returns 9.2/9.6/9.8/10.8 or height-formulas per "sceneRole" property (PluginEditorPanels.cpp:3148-3162); EditorLookAndFeel hardcodes 12.5 combo / 15.0 popup (PluginEditor.h:1868-1880).

## 3. Shape language

- **Corner radii: ~25 distinct values, 1.0–10.0**, incl. 2.2, 2.6, 4.8, 5.4, 5.8, 7.2, 7.5, 7.6, 8.2, 8.4, 8.5, 8.6, 8.8. The scene L&F alone uses four radii for four button roles (chip 6.0, tool 7.0, slot 8.4, transport 8.6 — PluginEditorPanels.cpp:3180). Modal values: fills 3.0/4.0/8.0/5.0; strokes R=4/5/3/8.
- **The panel recipe is maximal** (drawPanel, both copies): fake drop shadow (black 20% translated 1.5px) + vertical two-tone gradient + white top-sheen gradient + THREE nested 1px strokes (bright grey 0xff70757a, accent-alpha ring, dark 0xff242424 inner). Called 15 times, plus the same recipe re-implemented for scene buttons (gradient + sheen + 2-3 nested strokes each, PluginEditorPanels.cpp:3197-3223) and combos (gradient + sheen + double stroke, 3312-3329).
- **Gradients: 15 explicit ColourGradient sites** beyond drawPanel — page background, 40px title bar with its own gradient (0xff3a3d41→0xff2e3135, PluginEditor.cpp:9799-9803), waveform backgrounds, grain windows, glow accents.
- Strokes: essentially all 1.0f, with stray 0.5/0.8/0.9/0.95/1.1/1.2/1.4/1.45 one-offs.
- No juce::DropShadow anywhere; all shadows are 1-1.5px offset black-alpha fills (reads as a faint smudge, not depth).

## 4. Spacing

- There is a **latent 4px rhythm**: removeFromLeft(4) ×37, removeFromTop(4) ×26, removeFromTop(2) ×23, gaps of 6 next most common; local `const int gap = 4` appears repeatedly (PluginEditorPanels.cpp:130, 13895, 15669...). reduced() mostly 1/2 then 4/6/8/10/12.
- But it is **not codified**: exactly two named layout constants exist in ~26k lines (kPatternCardHeight 96, kPatternCardGap 6, PluginEditor.cpp:36-37), and odd literals leak everywhere (removeFromLeft(3), removeFromTop(1), gapY = 1).
- Row/control heights cluster at 16/18/20/22/24 with 22 and 18 most common — several interactive controls sit at 16-18px tall, thin for a live-performance hit target.

## 5. LookAndFeel situation

- **Three custom L&F classes**, none sharing code or tokens:
  1. `EditorLookAndFeel` (PluginEditor.h:1868) — overrides only two fonts; the real global styling is ~30 setColour defaults in setupLookAndFeel (PluginEditor.cpp:9740-9772), several of which hardcode hexes that shadow the tokens (button 0xff404448, slider track 0xff4c4c4c, popup bg 0xff202428, tab outline 0xff575c61).
  2. `ColoredKnobLookAndFeel` (PluginEditor.h:209, ~250 lines) — flat-dark rotary + bipolar/mod-overlay linear sliders, per-strip tint; hardcodes its own greys (0xff2a2a2a body, 0xff515151 ring, 0xfff2f2f2 pointer). Notably this knob is already flat/modern — the newest-looking element in the app.
  3. `SceneControlLookAndFeel` (PluginEditor.h:1514, impl PluginEditorPanels.cpp:3138-3345) — role-tagged ("sceneRole" property) buttons/combos, but painted in the glossy gradient+sheen+triple-stroke style.
- Everything else is **per-widget setColour spam: 612 calls** (260 + 352). That is the dominant styling mechanism; a token change today reaches only a fraction of the UI.
- Tabs (both tiers) use stock JUCE_V4 tab drawing with recolored outlines (PluginEditor.cpp:9768-9772) — bright 0xff575c61 boxes around tab buttons.

## 6. Why it reads as dated — specifics

1. **Glossy 2008-era surfaces**: vertical two-tone gradient + white top-sheen on every panel, button, and combo (drawPanel, scene L&F). Modern dark UIs use flat fills separated by elevation, not simulated curvature.
2. **Triple nested 1px outlines** per panel, with the outermost a bright mid-grey (0xff70757a) — everything is boxed, borders compete with content, and the accent ring at 22% alpha just muddies edges.
3. **Micro bold type**: 6-8pt bold labels (12+ sites), 5.8-6pt badges, and 36 sizes with no scale — dense, shouty, and unreadable at a glance on stage.
4. **173 unmanaged greys** — surfaces don't sit on a coherent elevation ramp, so nesting depth is illegible; adjacent panels differ by ~1 hex step for no reason.
5. **25 corner radii** — chips/buttons/panels each rounded differently (6.0 vs 7.0 vs 8.4 vs 8.6 within one L&F), so nothing feels like one family.
6. **Fake 1px offset shadows** instead of real depth; **gradient title bar**; **stock JUCE tab bar** with outlined tabs — all classic JUCE-default tells.
7. **Accent inflation**: amber kAccent + 7 strip colors + 9 ControlMode colors + 4+ transition colors + red/green transport colors all fight; there is no reserved "look here" channel.

## Restyle leverage points (for the proposal)

- Highest-leverage single fix: make PluginEditor.cpp include PluginEditorStyle.h and delete the duplicated anonymous-namespace tokens/drawPanel (PluginEditor.cpp:22-60) — then the header becomes the one place to flatten drawPanel (kill sheen + 2 of 3 strokes), instantly de-glossing 15 panels.
- Second: setupLookAndFeel (PluginEditor.cpp:9740-9772) + styleUiButton/styleUiCombo + SceneControlLookAndFeel are the only 4 places most buttons/combos get painted — restyling those covers the majority of interactive chrome without touching the 612 setColour sites.
- Tokenize: an elevation ramp (4-5 greys), semantic kPositive/kRecord/kInfo (replacing the green/red/blue ad-hocs), one radius pair (e.g. 4/8), a 4px spacing unit, and a 4-step type scale (e.g. 9/10/11/13 with weight, not 0.2pt increments, as hierarchy) — all consistent with the latent patterns already in the code, so it's a mapping exercise, not a redesign of layouts.
- The flat ColoredKnobLookAndFeel knob is already the target aesthetic; the proposal can cite it as the in-app reference style.
- Duplicates to consolidate while restyling: patternControlEventColour (PluginEditor.cpp:63 / PluginEditorPanels.cpp:478) and the 7-color strip palette (PluginEditor.cpp:1483, ~7609).

# mlrVST-modern UI Information Architecture Audit
Sources: /Users/e2_18/Downloads/mlrVST-modern/Source/PluginEditor.cpp (editor + StripControl/FXStripControl + MonomeControlPanel/PatternControlPanel/GroupControlPanel), PluginEditor.h (all class declarations, windowWidth/Height at lines 1936-37), PluginEditorPanels.cpp (PathsControlPanel line 18, SceneControlPanel 4112-13560, PresetControlPanel 13568, MacroControlPanel 13938, GlobalControlPanel 14798, MonomePagesPanel 15480), PluginEditorStyle.h.

## 1. Screen map (default 1000x1052, resizable 1000x620 - 1920x1400)

Vertical budget, top to bottom (MlrVSTAudioProcessorEditor::resized, PluginEditor.cpp:9844-9888):
- **Title bar, 40px, always visible** — painted directly (paint(), :9791): "mlrVST" logo, "Performance Slicer" tagline, version/build string right-aligned. Zero interactive content. Pure branding overhead.
- **6px margins all around.**
- **topTabs (juce::TabbedComponent, tab bar 28px, fixed total 184px)** — 6 tabs, ONE visible at a time in a 988x156 content area: Global Controls (default) / Macros / Presets / Monome Device / Paths / Scene. Created at :9477-9486.
- **6px gap.**
- **mainTabs (second TabbedComponent, tab bar 28px, gets all remaining height ≈ 754px, strip area ≈ 726px)** — Play / FX / Patterns / Groups. Created at :9587-9632. Patterns and Groups tabs are removed while scene mode is on (refreshSceneModeLayout :9643).
- **MonomePagesPanel, bottom 50px, always visible** — 14 page slots (NumControlRowPages=14), each a mode button + tiny up/down reorder arrows (13x9px). Doubles as the only always-on "what page is my monome on" indicator.

Special state: **scene-mode fullscreen** (:9858-9872) — when scene mode is enabled and the Scene top tab is current, topTabs takes the ENTIRE area, mainTabs (all strips) is hidden. Scene mode also force-switches topTabs to Scene and removes Patterns/Groups from mainTabs.

Two identically-styled stacked tab bars (6 + 4 tabs) is the core IA problem: 10 destinations, no visual hierarchy between "settings drawer" (top) and "workspace" (bottom), and the split is not setup-vs-perform — Scene (live) sits next to Paths (setup).

## 2. Redundancy / dead weight

- **Preset access exists 3x**: PresetControlPanel grid (112 slots, 16x7, 16px-tall buttons); the monome hardware preset page; and MonomePagesPanel declares a full duplicate preset grid (presetViewport/presetButtons, PluginEditor.h:985-989) that is **dead code** — never addAndMakeVisible'd, never laid out (only PresetControlPanel's viewport gets bounds, PluginEditorPanels.cpp:13727).
- **monomeGrid (MonomeGridDisplay) is created but never added to the view** (:9460-9461, comment "Don't add to view - saves space") yet still gets updateFromEngine() every 50ms timer tick when a monome is connected (:9977-9982). Dead component + wasted work.
- **FX tab master-duck header is permanently zero-bounds**: FXPanel::resized sets masterDuckLabel/masterDuckTriggerBox to {} unconditionally (:9560-9561). The masterDuckTriggerStrip parameter is only reachable via that invisible combo; per-strip "Follow Master" buttons reference a master nobody can set from the GUI.
- **Hidden combos back the header chips**: playModeBox, directionModeBox, groupSelector are always setVisible(false)/setBounds({}) (:4041-4043, :4100-4102) and exist only so the identity chips' popup menus can write through their attachments. Harmless but confusing for maintenance.
- **Groups tab**: a full ~754px main tab holding 12 controls (4x mute + volume + status label). Group assignment already lives on every strip header chip. Massive space-to-content mismatch.
- **Patterns tab** duplicates the monome pattern-recorder page; GUI cards are 4 rows of Rec/Play/Stop/Clear + timeline. Its timerCallback calls resized()+repaint() every tick (:6899-6907) — layout thrash smell.
- **Four visible gain stages**: per-strip trim (header ValueReadoutSlider) + per-strip volume knob + group volume + master volume. Trim vs Vol distinction is invisible at a glance.
- **Global Controls panel mixes tiers**: performance controls (master vol, input monitor + meters, quantize, swing, root/scale) share one 156px panel with pure setup (stretch backend, resampling quality, output routing, flip tempo-match policy, 4 transient-detection combos, crossfade/trigger-fade, tooltips toggle, gesture editor button, momentary toggle).

## 3. Performer-needs vs setup-time classification

**Mid-set (must be ≤1 gesture, glanceable):** Play strips (trigger feedback, waveform, LED overlay); strip volume/pitch/speed knobs; identity chips (mode/direction/group); MonomePagesPanel active-page indicator; scene slots + NOW/NEXT/REC status strip (Scene panel); pattern arm; group mutes; quantize; master volume; macro knobs (performance surface for MPK-mini CCs).
**Setup-time (pre-gig, then never):** Monome Device (connect grid/arc, rotation, refresh — once per session); Paths (pinned default folders per strip x 3 modes — a 14-row file-path table); Global's transient method/sensitivity/snap/spacing, stretch backend, resampling quality, output routing, flip tempo-match mode, crossfade lengths, tooltips, gesture editor; Macro CC learn + target assignment (the knobs are live, the wiring is setup); Preset name/rename/delete/export/init row.
**Hybrid:** Presets (grid load = live; management row = setup); FX (filter freq/res/morph = live; duck attack/release/ratio, delay low/high cut = mostly set-and-forget); Scene chain editing (pre-arranged) vs scene firing (live).

Verdict: of the 6 top tabs, 2 are pure setup (Monome Device, Paths), 1 is mostly setup (Global's right two-thirds), and the tab UI gives them equal billing with Scene and Macros.

## 4. Strip row anatomy (StripControl::resized, :3800-4509)

Per row at 6 strips ≈ 120px, at 14 strips ≈ 51px (resized() bails entirely below 50px — 14-strip layouts are at the knife edge; a 620px-tall host window with 14 strips gives ~26px rows = blank strips).

- **Header, 19px full width**: strip label 30px; chip buttons (popup menus): MODE 54 / DIR 52 / GRP 38 / ROLE 44 / NOTE 38 / TIMING 44 (conditional); trim readout slider 48-58px; sample-name label takes the rest. Chips are 17px tall — small targets for stage use.
- **Left: waveform** (width minus 228px) — WaveformDisplay with playback head, loop points, slice markers, LED overlay painted on top, grain HUD, loop-pitch overlay, zoom/drag interaction, drag-and-drop target, double-click actions. This is the one genuinely glanceable element.
- **Right: 228px controls column**, contents swap by play mode:
  - Loop/One-shot/Gate: Load button + TIME/transient toggle (18px row); tempo label "AUTO"/"4.0b" (22px); record-bars combo 70 + REC 46 + tempo-match override 46 + pitch-backend override 52 crammed in one 18px row; knobs row 30px with up to 6 rotaries (~33px each): Vol/Pan/Pitch/Speed/Scratch/Slice + 9px label row; 10px record-length label.
  - Step: pattern-length combo + draggable number box + Vol/Pan/Attack/Decay/Release knobs.
  - Grain: entire column becomes a 3-tab micro-UI (Pitch/Space/Shape, 13px tabs) with 13px slider rows — 13 grain params + sync toggle at ~9-20px row heights. Densest UI in the plugin.
  - Modulation lane view (monome mod page active): whole row swaps to a mod-sequencer editor — 6 sequencer tabs 14px + ~6 rows of 16px label+combo/slider pairs, waveform hidden.
- **FX tab row** (FXStripControl::resized :5593): three columns — Filter (enable, algo combo, Freq/Res/Morph 64px knobs), Delay (mode, sync, 5x label+slider rows), Duck (enable, follow, source, 5x rows). ~26 controls per strip x 14 strips.

Cramped verdict: knobs 28-35px and rows 13-18px violate the stated glanceability/hit-target priority everywhere on the right column; the grain and mod-lane micro-UIs are the worst offenders.

## 5. Navigation cost for common flows

- **Load sample**: 0 tabs — Load button on every strip (Play is default) or drag-and-drop. Cost: 1 click + dialog. Good.
- **Tweak a filter**: mainTabs→FX (1 click) + find strip row + drag. Cost: 2. Penalty: you lose ALL waveform/playhead visibility while on FX — Play and FX are mutually exclusive full-page siblings.
- **Save preset**: topTabs→Presets (1 click), then Store or Shift+click a slot (1 click, name optional). Cost: 2-3. Load preset: 2 clicks.
- **Arm pattern**: mainTabs→Patterns (1) + Rec (1). Cost: 2 — and the tab vanishes in scene mode (hardware page becomes the only route).
- **Change quantize / master volume**: 0-1 clicks if Global tab is still current, but any Macros/Scene/Presets use replaces it — the most-used global controls share a single 156px slot with 5 other panels.
- **Tweak a macro then adjust quantize**: 2 tab switches, mutually exclusive views.
- **Scene firing**: monome pages bar always reachable; GUI scene slots need topTabs→Scene (auto-forced in scene mode). In scene fullscreen you cannot see strips at all.
- **Mute a group from GUI**: mainTabs→Groups (1) + Mute (1); or nothing on the strip itself (chip only reassigns).

## 6. Streamlining candidates (ranked, restyle/token-level feasible first)

1. **Turn the 40px title bar into a status/transport strip** (paint-level + a few small components): quantize combo, master vol mini-slider, grid-connected dot, loaded preset name, scene NOW/NEXT when armed. Kills the "Global tab must stay open" problem without moving panels.
2. **Merge Monome Device + Paths (+ Global's setup columns) into one "Setup" top tab** — Monome panel is ~10 controls in 988x156 (mostly empty); Paths is a rarely-touched table. Drops topTabs from 6 to 4 (Perform-Global / Macros / Presets / Setup, Scene) and makes tier-1 purely live-relevant. Tab add/remove is cheap (same pattern as refreshSceneModeLayout already uses).
3. **Delete the Groups main tab; give the strip group chip a right-click/long-press mute and add a 4-button group-mute cluster to the new status bar.** 12 controls do not justify a workspace tab.
4. **Demote Patterns tab to a rail or overlay** (its cards are 4x ~90px), or fold pattern arm buttons into the status bar; keeps mainTabs at Play/FX only — matching the strips-first mental model.
5. **Strip row de-densification** (targeted layout edit, no rewrite): keep header chips (good pattern — popup menus on chips are exactly right for live), but cut the right column to Vol/Pitch/Speed + a "…" disclosure that opens the full parameter set (record, overrides, grain pages, step envelope) as a row-height overlay over the waveform. Overrides (tempo-match, pitch-backend) are setup-tier and should leave the always-visible surface.
6. **FX as per-strip disclosure on Play** instead of a parallel 14-row page — solves the lose-the-waveform problem; alternatively (cheaper) keep the FX tab but sync its scroll/highlight with the Play strip hovered.
7. **Dead-code cleanup with zero UX risk**: remove MonomePagesPanel's unused preset grid members, un-created monomeGrid updates, FX master-duck zero-bounds header (either lay it out or delete the parameter's GUI); stop PatternControlPanel::timerCallback calling resized() every tick.
8. **Preset grid rescale**: 112 slots x 16px buttons is a setup-density grid in a live panel; an 8-16-slot "performance bank" row (larger targets) + "all presets" disclosure fits the existing panel.
9. **Differentiate the two tab tiers visually** (pure LookAndFeel: tab depth, weight, accent underline for the workspace tier vs quieter pill style for the settings tier) so the hierarchy reads even if no panels move.
10. **MonomePagesPanel arrows (13x9px) are the smallest targets in the app** — reorder is setup-time; move reordering behind a drag gesture or into Setup, keep the bar as pure page indicator/switcher with full-height buttons.

Constraint check: items 1-4, 7-10 are token/LookAndFeel/targeted-layout edits; item 5 is a contained StripControl::resized refactor (visibility logic already mode-switches everything); item 6 has a cheap variant. Scene panel structure untouched throughout (restyle only, per prior redesign).

## Proposals — system lens

### [high impact / medium effort] Single style source: unify the header and add one shared AppLookAndFeel
Prerequisite that makes every other proposal a one-point edit. (1) Make /Users/e2_18/Downloads/mlrVST-modern/Source/PluginEditor.cpp include PluginEditorStyle.h and delete its anonymous-namespace token copies + duplicate drawPanel (PluginEditor.cpp:22-60). (2) Move the twice-duplicated palettes into the header: patternControlEventColour (PluginEditor.cpp:63 / PluginEditorPanels.cpp:~478) becomes PluginEditorStyle::controlModeColour(mode); the 7-color strip palette (PluginEditor.cpp:1483 and ~7609) becomes constexpr kStripPalette[7]. (3) New class AppLookAndFeel : juce::LookAndFeel_V4 (declared in PluginEditorStyle.h, impl in a new PluginEditorStyle.cpp) owning drawButtonBackground, drawComboBox, drawPopupMenuItem, drawLinearSlider, and drawTabButton — all reading tokens only. EditorLookAndFeel (PluginEditor.h:1868) and SceneControlLookAndFeel (PluginEditor.h:1514, impl PluginEditorPanels.cpp:3138-3345) become thin subclasses that keep only their font/role-sizing overrides and delegate painting to AppLookAndFeel primitives — this deletes the scene panel's private gradient+sheen+triple-stroke re-implementation without touching its recently-redesigned structure. (4) Re-point the ~30 setColour defaults in setupLookAndFeel (PluginEditor.cpp:9740-9772) at tokens, deleting the shadow hexes 0xff404448 (button), 0xff4c4c4c (slider track), 0xff202428 (popup bg), 0xff575c61 (tab outline). styleUiButton/styleUiCombo in the header are rewritten to use tokens instead of their hardcoded 0xff3b4146/0xff4a5258/0xff353b42/0xff6a7076. The 612 per-widget setColour calls are NOT swept up front — they get retired opportunistically because the L&F defaults now match the tokens.

### [high impact / medium effort] Elevation ramp: replace 173 greys with 6 surface tokens
New neutral ramp in PluginEditorStyle.h, cool-neutral like today, one step per nesting level so depth is legible without gradients: kBg 0xff141619 (flat page background — replaces the kBgTop/kBgBottom gradient), kWell 0xff1b1e21 (recessed content: waveform backgrounds, slider tracks, viewports, the topTabs pill track), kSurface 0xff23262a (panels/cards — chosen as the modal value of today's near-duplicates so most panels visually barely move), kSurfaceHi 0xff2c3034 (resting interactive: buttons, combos, chips), kSurfaceHover 0xff363b40 (hover = exactly one ramp step up), kStroke 0xff34393e (hairline separators — demotes the bright 0xff70757a kPanelStroke, which currently outshouts content). Rules: adjacent surfaces must differ by >=1 ramp step or be separated by a kStroke hairline; never invent a grey between steps. Migration is a nearest-luminance mapping table for the ~45 near-duplicate greys between 0xff0e1114 and 0xff4a4d50 (e.g. 0xff232629/0xff23262a/0xff23282d/0xff24272c all -> kSurface); kPanelTop/kPanelBottom/kSurfaceDark are deleted, kPanelStroke aliased to kStroke during transition.

### [high impact / small effort] Keep amber, enforce accent discipline, tokenize the semantic colors
Keep kAccent 0xffffb347: it is a strong identity, warm against the cool ramp, and high-visibility on a dark stage — the problem is inflation, not the hue. New rule: amber means exactly 'selected / focused / primary action'; it stops being the ControlMode fallback and misc color (add kDataNeutral 0xff8a9096 for fallback/unassigned). New semantic tokens folding the ad-hoc values: kLive 0xff77c982 for play/active/connected (folds 0xff76be7e x10, 0xff88d96b, 0xff58c96d, 0xff6eb676 — monome status PluginEditor.cpp:6486-6493, transport heads 7024/7123); kRecord 0xffd9584c (folds 0xffd46b62 x9, 0xffd45b5b, 0xffc95252) with the dim blink partner computed as kRecord.withMultipliedBrightness(0.5f), deleting hardcoded 0xff743636/0xff6d3434 (PluginEditor.cpp:4839, PluginEditorPanels.cpp:7374); kInfo 0xff64b9f0 (folds 0xff6bbcff Speed, 0xff74d6ff Delay, 0xff3bd5ff, 0xff41b7e8). The strip and ControlMode palettes survive (they are data encodings performers learn) but get normalized into one saturation/brightness band (~60-70% sat, ~70-78% brightness) so no data color is louder than amber. Result: one reserved 'look here' channel, three semantic channels, two data palettes — nothing else.

### [high impact / medium effort] Five-step type scale, 9pt stage floor, mono numerics
Replace 36 ad-hoc sizes with role helpers in PluginEditorStyle.h — juce::Font PluginEditorStyle::font(Role, bool emphasized=false): Micro 9.0 plain (uppercase micro-labels, badges — the absolute floor; every 5.8-8.0pt call site, incl. the 6.0pt scene badges at PluginEditorPanels.cpp:3258, moves UP to 9.0), Label 10.0, Body 11.5, Title 13.0 bold, Display 17.0 bold (title-bar/big readouts, replaces 23.0). Weight becomes the hierarchy channel: plain is default, bold only for Title/Display and active/selected states — today bold-everywhere means weight carries zero information and 0.2pt size increments do all the work. Numeric readouts (trim dB, tempo 'AUTO'/'4.0b', record-length, macro values) get kTypeMono: juce::Font(juce::Font::getDefaultMonospacedFontName(), size, plain) so values stop jittering in width and read at a glance.
