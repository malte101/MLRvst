# mlrVST-modern — Play Mode Deep Audit (2026-08-11)

Bug + improvement audit of every strip play mode (Loop, OneShot, Gate, Step, Grain, Sample/Flip)
plus cross-mode switching. One specialist audit per mode; every major finding adversarially
verified (refute-by-default) by an independent re-trace. Previously-known issues (StepSampler
filter race, sample-load lock, group-mute gating, scene/monome findings) were excluded by design.

**Totals: 29 confirmed bugs, 22 minor findings, 36 improvement proposals.**

## Mode: loop

**How it works:** Loop mode is host-PPQ-slaved, not an integrator. triggerAtSample() stores an absolute anchor (ppqTimelineOffsetBeats) so pressed column = hostBeat phase + offset; process() re-derives the playhead PER SAMPLE from host PPQ (tempo factors cancel: pos = ppqElapsed*sampleLength/beatsForLoop, so tempo changes and long playback are drift-free while anchored). Speed != 1 (|v-1|>1e-3) or any scratch gesture flips to a free-running sample integrator pinned at flip time and hard-snapped back to the PPQ map on return. Per-sample pipeline: raw timeline phase -> direction map (reverse=mirror, pingpong=2L reflect, random modes) -> playhead-traversal ratio (slice-quantized speed handoffs w/ micro-blend) -> rearrange/stutter-slice lock -> slice envelope + resample-pitch segment warp -> interpolated read (whole-buffer-wrapping cubic). Inner loops (<16 cols) get an equal-power pre-roll wrap crossfade; full loops get none. Retriggers arm a dual blend (old-position re-read + rendered-output tail fader); stop(false) is a 12 ms crossfader fade with deferred playing=false (stopAfterFade). Swing/Bungee tempo-match can swap the read source to offline-stretched caches rebuilt synchronously inside process(). Quantized triggers come from QuantizationClock events; processBlock splits blocks at event samples so triggers land sample-accurately. Scratch release in Loop mode returns via reverseScratchToTimeline (rate-blended reverse ramp) then snapToTimeline re-seats all anchors.

### CONFIRMED — Source/AudioEngine.cpp:8408

### CONFIRMED — Source/AudioEngine.cpp:7190
The PPQ-anchored per-sample position multiplies the ABSOLUTE timeline beat count by the instantaneous smoothed speed (rawBase = timelineBeats * timelineRate / beatsForLoop * sampleLength), so any deviation of smoothedSpeed from exactly 1.0 shifts the playhead by an amount proportional to how long the session has been running.

*Trace:* Fully traced and confirmed. Line 7190 computes rawBase = ((timelineBeats * timelineRate) / beatsForLoop) * sampleLength, where timelineBeats = currentPpq + ppqTimelineOffsetBeats (7186) is the absolute host beat count and timelineRate = |rateMultiplier| (7187) = |smoothedSpeed.getNextValue()| per sample (7044, 6791), so position offset = timelineBeats * (rate-1) beats, growing with session time. The bypass gate speedBypassPpq (6539) tests the atomic TARGET playbackSpeed (6534, written at 9878), not the smoothed value; setPlaybackSpeed ramps smoothedSpeed via setTargetValue (9880) over 50 ms (reset(sampleRate, 0.05) at 1980). Returning the target to exactly 1.0 therefore re-enters the anchored path (ppqTimelineAnchored is set true for all normal non-OneShot PPQ triggers, 8155) while smoothedSpeed still ramps 2.0->1.0: at host beat 500/44.1kHz, rawBase moves about 500*4.5e-4/4 = 5.7% of sampleLength per sample, wrapped into the loop by mapPlaybackPositionInLoop (6181) — ~50 ms of full-loop scrub noise, worse later in the set. The block-level snap at 6563-6573 uses timelineBeats/beatsForLoop with NO rate factor, disagreeing with the per-sample audio path, and the transition block (6545-6587) neither resets smoothedSpeed (no setCurrentAndTargetValue) nor arms armTriggerOutputBlendLocked (arming sites are only 5701/5713/5807/8027/8223/9720/9737). Additionally, any steady speed inside the 1e-3 dead zone but not exactly 1.0 (e.g. 1.0005) stays anchored and accrues unbounded drift of timelineBeats*0.0005 beats.

*Fix:* Never scale absolute timelineBeats by the instantaneous rate. Keep the anchored path at rate 1.0 (drop timelineRate from lines 7190/7194, matching the block-level snap at 6570), and route speed offsets through the trigger-relative/integrator path only, or accumulate (rate-1) into a persistent phase-offset variable advanced per sample so only elapsed time is scaled. On the return-to-unity transition at Source/AudioEngine.cpp:6545-6587, call smoothedSpeed.setCurrentAndTargetValue(1.0f) and arm armTriggerOutputBlendLocked with the standard trigger fade so the snap is declicked.

### Minor findings
- **Source/AudioEngine.cpp:7384** — The loop-wrap crossfade is disabled for full-sample loops: the pre-roll blend requires loopCols < MaxColumns, so the default 16-column loop wraps by hard content jump (Resampler wraps interpolation indices mod buffer, but there is no amplitude/content blend across the seam). *Scenario:* Load any stem that is not perfectly loop-cut (file with silence-trimmed edges, non-zero start/end samples). Every beatsPerLoop bars the playhead jumps from sampleLength-1 to 0 and the end-of-file waveform butts against the start-of-file waveform - a click each cycle. Inner loops (<16 cols) get a proper equal-power pre-roll crossfade; the full loop, the most common case, gets none (captured live loops are pre-crossfaded by LiveRecorder, loaded files are not). *Fix:* Allow the existing pre-roll crossfade when loopCols == MaxColumns, with the pre-roll wrapping to the buffer tail (the wrap at line 7408 already handles negative pre-roll).
- **Source/AudioEngine.cpp:5327** — In Reverse direction mode the trigger anchor is not mirror-compensated: triggerAtSample builds ppqTimelineOffsetBeats so the UNmapped phase equals the pressed column, but mapLoopPositionForMode then returns loopLength - wrapped, so audible playback starts at the mirrored position. *Scenario:* Loop mode, direction Reverse, 16-column loop: press column 4 - the playhead audibly starts at the column-12 slice (loopLength minus target) and walks backward from there, not backward from the pressed slice. Muscle memory from Normal mode (press = hear that slice) breaks; combined with the mirrored loop-range display (getEffectiveLoopDisplayStartColumn) the mapping is doubly confusing mid-set. *Fix:* When directionMode == Reverse (or the reverse half of PingPong), compute the trigger offset against the mapped position (use loopLength - target when deriving triggerOffsetRatio / ppqTimelineOffsetBeats) so the pressed column is what sounds.
- **Source/PluginProcessorLoopPitch.cpp:758** — Loop-pitch Sync timing 'NextLoop' detects the loop boundary as currentColumn < lastObservedColumn, which fires on nearly every column step when the strip runs in Reverse (columns decrease monotonically) and mis-times in PingPong. *Scenario:* Strip is a Sync-role loop in Reverse direction with pending retune (global root changed). Instead of waiting for the loop's wrap point, the column comparison sees 'decrease' on the very next block and retunes immediately - 'NextLoop' silently behaves like 'Immediate', re-pitching mid-phrase during a set. *Fix:* Detect wrap using the strip's normalized loop phase (getLoopPhaseNormalized decreasing past 0 in the traversal direction) instead of raw column ordering, or branch on directionMode.

### Improvements
- **[high impact / small effort] Wrap crossfade for full-sample loops** — Remove the loopCols < MaxColumns gate at AudioEngine.cpp:7384 so the existing equal-power pre-roll blend also covers the default 16-column loop; pre-roll positions before sample start already wrap to the buffer tail. Keep it disabled when the sample was captured by LiveRecorder (those are pre-crossfaded) via a per-sample flag if double-fading is a concern.
- **[high impact / small effort] Declick every stateful snap (choke-retrigger, loop-geometry change, unity-speed return)** — Three call-site fixes reusing existing machinery: (1) trigger paths restart the crossfader fade-in from current gain when a stop fade is active; (2) realignToPpqAnchor arms armTriggerOutputBlendLocked(~1.5 ms) so quantized inner-loop set/clear is blended; (3) the speedPpqBypassActive flip block arms the same blend when hard-snapping back to the PPQ timeline. All three are one-line arms of already-proven faders.
- **[high impact / medium effort] Background-render swing and tempo-match caches** — Convert rebuildSoundTouchSwingCache/rebuildLoopTempoMatchCache from synchronous in-process() renders to the request/install pattern already used by the SoundTouch/Bungee/Signalsmith pitch caches: process() only checks validity and posts a render request keyed by (swing, division, geometry, tempo-quantized-to-~0.1bpm); a worker renders and installs under bufferLock with startPitchCacheOutputBlendLocked. Quantize the tempo key so host tempo ramps do not thrash rebuilds.
- **[high impact / medium effort] Rate-correct anchored playback (kill the unity-return sweep)** — Replace rawBase = timelineBeats * timelineRate / beatsForLoop * sampleLength with a per-strip phase accumulator: anchored mode always maps timelineBeats at rate 1.0, and any speed offset accumulates into a beats-offset integrated per sample (offset += (rate-1) * ppqPerSample). This makes speed rides phase-continuous both directions, removes the absolute-PPQ-proportional error, and lets the 1e-3 unity gate disappear entirely.
- **[medium impact / small effort] Unify speed math across PPQ and free-run paths for non-native sample rates** — Delete sampleRateRatio from effectiveSpeed (AudioEngine.cpp:7046) and from the scratch-return predictions (8653/8861: use playbackSpeed * autoWarpSpeed), making the integrator path advance source samples identically to the PPQ paths. A 48k stem in a 44.1k session then keeps grid lock through speed moves, scratches, and PPQ dropouts.
- **[medium impact / small effort] Honor the pressed column in Reverse/PingPong triggers** — In triggerAtSample, when directionMode maps positions (Reverse, reflected half of PingPong), derive triggerOffsetRatio/ppqTimelineOffsetBeats from the inverse mapping (loopLength - target; for PingPong also select the forward half of the 2L period) so the slice under the performer's finger is what sounds, matching Normal-mode muscle memory.

## Mode: oneshot + gate

**How it works:** OneShot/Gate share the strip voice: monome press -> onButtonPress (hold state) + triggerStrip (PluginProcessor.cpp:5790), which either fires triggerAtSample immediately or schedules a QuantisedTrigger; pending events are popped once per audio block (AudioEngine.cpp:13693) and fired sample-accurately mid-block (14128), with group choke applied at fire time via stop(false) 12ms fade. process() derives positionInLoop from PPQ (anchored for Gate, trigger-relative for OneShot); Gate wraps/loops while held, OneShot stops when positionInLoop crosses [0, loopLength) (7330). Gate stop comes only from the MonomeController key-up (2491) calling stopStrip(strip, true) = clear pending triggers + stop(true) hard mute; pattern replay note-offs use stop(false). Retrigger clicks are handled by a dual-read crossfade (retriggerBlend) plus SampleFader tails; stop(true) resets all faders and silences at the next block boundary.

### CONFIRMED — Source/AudioEngine.cpp:13693

*Trace:* Full path verified. (1) Gate press with quantize schedules a trigger into QuantizationClock::pendingTriggers (PluginProcessor.cpp:5926, AudioEngine.cpp:1050-1142). ### Minor findings

## Mode: sample

**How it works:** Flip/Sample mode: per-strip SampleModeEngine owns the loaded sample, a slice model (Uniform/Beat/Transient/Manual, 16-slot visible banks or a legacy MLR loop window), and 2 playback voices.
Grid press (message thread) captures visible slice id+startSample, schedules on the quantize clock; processBlock fires sampleModeTriggerCallback (audio thread) -> triggerRecordedSlice/triggerVisibleSlice resolves the slice (nearest-start fallback survives re-slices) and triggers a voice, releasing all others with a ~2 ms crossfade.

OneShot voices end at the slice end fade; Loop voices free-run (no PPQ re-anchor). Stops: stopSampleModeStrip (faded choke/release) vs a hard per-block stop(true) whenever host transport is not playing.
All slice/cue/warp/window state sits behind one CriticalSection shared by the UI (30 Hz snapshots, edits, in-lock re-analysis) and the audio thread (render + trigger resolution) - the mode's central structural risk.
